# Chapter 03. 디렉터리와 파일 사용

## 1. 학습 개요

Linux 파일 시스템의 기본 구조와 파일의 종류를 학습하고,
절대 경로와 상대 경로를 이용하여 디렉터리를 이동하는 방법을 익혔다.

또한 파일과 디렉터리의 생성, 복사, 이동, 삭제를 직접 실습하고
하드 링크와 심볼릭 링크의 차이를 확인하였다.

---

## 2. 핵심 개념

### 2.1 파일 시스템

파일 시스템(File System)은 저장 장치에서 파일과 디렉터리를
구조적으로 저장하고 관리하기 위한 체계이다.

Linux에서는 ext4와 같은 디스크 기반 파일 시스템뿐만 아니라
`/proc`, `/sys`와 같이 시스템 정보를 파일 형태로 제공하는
가상 파일 시스템도 사용한다.

### 2.2 파일 시스템의 기본 구조

파일 시스템의 구조를 단순화하면 다음과 같이 이해할 수 있다.

```text
파일 시스템
├── Super Block
│   └── 파일 시스템 전체 관리 정보
│
├── inode
│   └── 파일의 메타데이터와 데이터 위치 정보
│
└── Data Block
    └── 실제 파일 내용
```

### 2.3 inode

inode는 파일을 관리하기 위한 정보를 저장하는 자료 구조이다.

주요 정보에는 다음과 같은 것들이 있다.

- 파일 종류
- 접근 권한
- 소유자와 그룹
- 파일 크기
- 시간 정보
- 실제 데이터의 위치를 찾기 위한 정보

inode 번호는 다음 명령으로 확인할 수 있다.

```bash
ls -i
```

파일 이름 자체는 inode에 저장되는 것이 아니라
디렉터리가 파일 이름과 inode를 연결하여 관리한다.

---

## 3. Linux 파일의 종류

Linux에서는 일반 파일뿐 아니라 디렉터리, 링크, 장치 등도
파일의 형태로 다룬다.

| 종류 | 설명 |
| --- | --- |
| 일반 파일 | 텍스트, 이미지, 실행 파일 등의 데이터 |
| 디렉터리 | 파일 이름과 inode 등을 연결하는 정보 관리 |
| 심볼릭 링크 | 다른 파일이나 디렉터리의 경로를 가리키는 파일 |
| 장치 파일 | 프로그램이 장치에 접근하기 위한 인터페이스 |

---

## 4. 주요 디렉터리

Linux의 파일과 디렉터리는 루트 디렉터리 `/`를 기준으로
트리 형태의 계층 구조를 가진다.

| 디렉터리 | 주요 역할 |
| --- | --- |
| `/` | 최상위 루트 디렉터리 |
| `/home` | 일반 사용자의 홈 디렉터리 |
| `/root` | root 사용자의 홈 디렉터리 |
| `/etc` | 시스템 및 프로그램 설정 파일 |
| `/dev` | 장치 파일 |
| `/proc` | 프로세스 및 커널 정보 |
| `/sys` | 장치 및 커널 정보 |
| `/boot` | 부팅 관련 파일 |
| `/tmp` | 임시 파일 |
| `/usr` | 프로그램, 명령어 및 라이브러리 |
| `/var` | 로그 등 자주 변경되는 데이터 |

`/`, `root`, `/root`는 서로 다른 개념이다.

```text
/       → 루트 디렉터리
root    → 관리자 계정
/root   → root 사용자의 홈 디렉터리
```

---

## 5. 경로 표현

Linux에서는 파일이나 디렉터리의 위치를 절대 경로와
상대 경로로 표현할 수 있다.

### 주요 표현

| 표현 | 의미 |
| --- | --- |
| `/` | 루트 디렉터리 |
| `~` | 현재 사용자의 홈 디렉터리 |
| `.` | 현재 작업 디렉터리 |
| `..` | 부모 디렉터리 |

### 절대 경로

루트 디렉터리 `/`부터 전체 경로를 표현한다.

```text
/home/student/Documents
```

### 상대 경로

현재 작업 디렉터리를 기준으로 경로를 표현한다.

```text
Documents
./Documents
../Documents
```

# 7. 직접 수행한 실습

> 아래 출력에서 실제 사용자 이름과 호스트명은 개인정보 보호를 위해
> `student@ubuntu-vm`으로 변경하였다.

## 7.1 현재 위치 확인 및 디렉터리 이동

먼저 `pwd`를 이용하여 현재 작업 디렉터리를 확인하였다.

```bash
student@ubuntu-vm:~$ pwd
/home/student
```

`cd`와 `~`를 이용하여 루트 디렉터리와 홈 디렉터리 사이를 이동해 보았다.

```bash
student@ubuntu-vm:~$ cd /
student@ubuntu-vm:/$ cd ~
student@ubuntu-vm:~$
```

인자 없이 `cd`를 실행해도 홈 디렉터리로 이동하는 것을 확인하였다.

```bash
student@ubuntu-vm:/etc$ cd
student@ubuntu-vm:~$
```

### 상대 경로 이동 중 발생한 오류

홈 디렉터리 `/home/student`에서 `/tmp`로 이동하기 위해
다음 명령을 실행하였다.

```bash
student@ubuntu-vm:~$ cd ../tmp
-bash: cd: ../tmp: 그런 파일이나 디렉터리가 없습니다
```

현재 위치가 `/home/student`이므로 `..`은 `/home`을 의미한다.

따라서 `../tmp`는 `/home/tmp`를 의미하지만 해당 디렉터리가 없어
오류가 발생하였다.

두 단계 위인 `/`로 이동한 후 `tmp`로 접근하도록 수정하였다.

```bash
student@ubuntu-vm:~$ cd ../../tmp
student@ubuntu-vm:/tmp$ pwd
/tmp
```

이 실습을 통해 상대 경로는 현재 작업 디렉터리를 기준으로
해석된다는 것을 확인하였다.

---

## 7.2 ls를 이용한 디렉터리 확인

파일과 디렉터리의 종류를 구분하기 위해 `-F` 옵션을 사용하였다.

```bash
student@ubuntu-vm:~$ ls -F
snap/  Documents/  Downloads/  Pictures/
```

디렉터리 자체의 상세 정보는 `-ld` 옵션으로 확인하였다.

```bash
student@ubuntu-vm:~$ ls -ld .
drwxr-x--- ... student student ... .
```

루트 디렉터리도 확인하였다.

```bash
student@ubuntu-vm:~$ ls -ld /
drwxr-xr-x ... root root ... /
```

Ubuntu에서는 `/bin`과 `/sbin` 등이 `/usr` 아래의 디렉터리와
연결되어 있는 것도 확인할 수 있었다.

```text
bin -> usr/bin/
sbin -> usr/sbin/
```

---

## 7.3 디렉터리 생성

먼저 하나의 디렉터리를 생성하였다.

```bash
mkdir temp
```

여러 디렉터리도 한 번에 생성할 수 있었다.

```bash
mkdir d1 d2
```

### 중간 디렉터리가 없을 때

다음과 같이 여러 단계의 디렉터리를 한 번에 생성하려고 하였다.

```bash
mkdir temp/mid/work
```

하지만 중간 디렉터리인 `mid`가 존재하지 않아 생성에 실패하였다.

```text
mkdir: 'temp/mid/work' 디렉터리를 만들 수 없습니다:
그런 파일이나 디렉터리가 없습니다
```

`-p` 옵션을 사용하여 해결하였다.

```bash
mkdir -p temp/mid/work
```

생성 결과를 확인하였다.

```bash
ls -R temp
```

```text
temp:
mid

temp/mid:
work
```

`mkdir -p`를 사용하면 필요한 부모 디렉터리까지 함께 생성할 수 있다는 것을 확인하였다.

---

## 7.4 rmdir을 이용한 디렉터리 삭제

빈 디렉터리는 `rmdir`로 삭제할 수 있었다.

```bash
rmdir d1 d2
```

하지만 내부에 파일이나 하위 디렉터리가 존재하는 디렉터리를 삭제하면
오류가 발생하였다.

```bash
rmdir temp
```

```text
rmdir: 'temp' 제거 실패: 디렉터리가 비어있지 않음
```

이를 통해 `rmdir`은 기본적으로 **빈 디렉터리를 삭제할 때 사용한다**는 것을 확인하였다.

---

## 7.5 파일 복사

`/etc/hosts` 파일을 실습용 디렉터리에 다른 이름으로 복사하였다.

```bash
mkdir ch03
cp /etc/hosts ch03/htest
```

복사한 파일을 다시 다른 디렉터리로 복사하였다.

```bash
mkdir temp3
cp ch03/htest temp3/
```

`-i` 옵션을 사용하면 기존 파일을 덮어쓰기 전에 확인할 수 있었다.

```bash
cp -i ch03/htest temp3/
```

```text
'temp3/htest'을(를) 덮어쓸까요? y
```

### 디렉터리 복사

디렉터리를 일반 `cp` 명령으로 복사하려고 하자 실패하였다.

```bash
cp temp3 temp
```

```text
cp: -r을 지정하지 않음. 'temp3' 디렉터리 생략
```

`-r` 옵션을 사용하여 디렉터리 내부까지 재귀적으로 복사하였다.

```bash
cp -r temp3 temp
```

이를 통해 파일 복사와 디렉터리 복사의 사용 방법이 다르다는 것을 확인하였다.

---

## 7.6 파일 이름 변경 및 이동

실습용 파일을 생성한 뒤 이름을 변경하였다.

```bash
mv data1 data1.org
```

`mv`는 이름 변경뿐 아니라 파일을 다른 디렉터리로 이동할 때도 사용할 수 있었다.

```bash
mkdir temp2
mv data1.org temp2/
```

```bash
ls temp2
```

```text
data1.org
```

따라서 `mv`는 상황에 따라 **파일 이동과 이름 변경** 두 가지 용도로 사용할 수 있다는 것을 확인하였다.

---

## 7.7 파일과 디렉터리 삭제

디렉터리를 일반 `rm`으로 삭제하려고 하자 실패하였다.

```bash
rm temp temp2
```

```text
rm: 'temp'을(를) 제거할 수 없습니다: 디렉터리입니다
rm: 'temp2'을(를) 제거할 수 없습니다: 디렉터리입니다
```

디렉터리와 내부 내용을 함께 삭제하기 위해 `-r` 옵션을 사용하였다.

```bash
rm -r temp temp2
```

삭제 전에 확인하면서 진행하는 `-i` 옵션도 실습하였다.

```bash
rm -ir temp1
```

이 실습을 통해 `rm -r`은 디렉터리 내부의 파일까지 삭제할 수 있으므로
사용할 때 주의해야 한다는 것을 확인하였다.

## 7.8 하드 링크와 심볼릭 링크 비교

원본 실습 파일을 만든 뒤 하드 링크 두 개를 생성하였다.

```bash
cp /etc/hosts test.org

ln test.org test.hd1
ln test.org test.hd2
```

심볼릭 링크도 생성하였다.

```bash
ln -s test.org test.sb
```

일반 복사본도 하나 생성하여 비교하였다.

```bash
cp test.org test.bak
```

inode 번호를 확인하였다.

```bash
ls -i test*
```

예시 결과:

```text
200001 test.bak
200002 test.hd1
200002 test.hd2
200002 test.org
200003 test.sb
```

실제 inode 번호는 시스템마다 다르지만,
하드 링크인 `test.org`, `test.hd1`, `test.hd2`가
동일한 inode 번호를 사용하는 것을 확인하였다.

반면 일반 복사본과 심볼릭 링크는 서로 다른 inode를 사용하였다.

```text
test.org ─┐
test.hd1 ─┼──→ 동일한 inode → 데이터
test.hd2 ─┘

test.bak ───→ 별도의 inode → 복사된 데이터

test.sb ────→ test.org 경로를 가리키는 심볼릭 링크
```

### 원본 이름 삭제 후 비교

원본 이름을 삭제하였다.

```bash
rm test.org
```

이후 심볼릭 링크에 접근하였다.

```bash
cat test.sb
```

```text
cat: test.sb: 그런 파일이나 디렉터리가 없습니다
```

심볼릭 링크가 가리키던 경로가 사라졌기 때문에 정상적으로 접근할 수 없었다.

반면 하드 링크는 여전히 동일한 inode와 데이터를 가리키고 있으므로
내용에 접근할 수 있었다.

```bash
cat test.hd1
```

이를 통해 하드 링크와 심볼릭 링크의 차이를 실제로 확인하였다.

## 8. 오류를 통해 확인한 내용

이번 실습에서는 정상적으로 실행된 명령뿐 아니라
잘못된 명령을 실행했을 때 발생하는 오류도 확인하였다.

| 상황 | 원인 | 해결 |
| --- | --- | --- |
| `cd ../tmp` 실패 | 현재 위치 기준으로 `/home/tmp`를 찾음 | 경로를 다시 확인하여 `../../tmp` 사용 |
| `mkdir temp/mid/work` 실패 | 중간 디렉터리가 존재하지 않음 | `mkdir -p` 사용 |
| `rmdir temp` 실패 | 디렉터리가 비어 있지 않음 | 내부 확인 후 적절한 삭제 방법 사용 |
| `cp temp3 temp` 실패 | 디렉터리 복사에 재귀 옵션이 없음 | `cp -r` 사용 |
| `rm temp` 실패 | 일반 `rm`으로 디렉터리 삭제 시도 | 필요할 경우 `rm -r` 사용 |
| 심볼릭 링크 접근 실패 | 링크가 가리키는 원본 경로 삭제 | 심볼릭 링크의 동작 방식 확인 |

오류 메시지를 단순히 넘기지 않고 현재 작업 디렉터리와 명령어의 동작 방식을 확인하면서 원인을 분석하였다.

## 9. 실습을 통해 배운 점

이번 Chapter에서는 파일과 디렉터리를 다루는 기본 명령어를 직접 사용하였다.

특히 다음 내용을 실습을 통해 확인하였다.

- 절대 경로는 `/`를 기준으로 하고 상대 경로는 현재 작업 디렉터리를 기준으로 한다.
- `mkdir -p`를 이용하면 존재하지 않는 부모 디렉터리까지 함께 생성할 수 있다.
- `rmdir`은 빈 디렉터리를 삭제할 때 사용한다.
- 디렉터리를 복사하려면 `cp -r`과 같이 재귀 옵션이 필요하다.
- `mv`는 파일 이동뿐 아니라 이름 변경에도 사용할 수 있다.
- `rm -r`은 디렉터리 내부까지 삭제하므로 사용 시 주의해야 한다.
- 하드 링크는 동일한 inode를 공유하지만 심볼릭 링크는 대상 경로를 가리키는 별도의 파일이다.
- 명령어 오류가 발생했을 때 현재 위치와 경로를 확인하면 원인을 파악하는 데 도움이 된다.

단순히 명령어의 형식을 외우는 것보다 직접 파일과 디렉터리를 생성하고
오류 상황을 확인하면서 각 명령어의 동작 차이를 이해할 수 있었다.
